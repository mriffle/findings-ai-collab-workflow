## Reporting

- **No bare p-values.** Every significance claim reports, together: an **effect size**, a **confidence interval** for that effect, and a **corrected** p-value. A p-value alone is not a result. (Mirrored in the finding `evidence` schema, conventions/findings.md §2.3.)
- **Always apply and name a multiple-testing correction.** Default **Benjamini–Hochberg (BH/FDR)** for omics-scale testing; name the method and the family it was applied over. Report q-values / adjusted p-values.
- **Report all tests run**, not only the significant ones. This feeds the exploration log (doc 03.6) and keeps the false-discovery burden visible — silently dropping the tests that didn't pan out is how multiplicity gets hidden.

## Descriptive characterization (the cohort)

Before any modelling, the metadata is characterized in full (Stage 1) — to produce figures and tables the scientist can publish *and* to expose the biases that constrain every downstream claim. Done thoroughly this means:

- **Every variable's distribution** — sample counts per categorical level; summaries/histograms for continuous variables (age, BMI, run order).
- **Pairwise structure that matters** — cross-tabulate the variable of interest against each covariate and against batch/run-order (sex × group, age × sex, group × batch). A publication-ready **cohort table ("Table 1")** breaks the design factors down by the primary grouping.
- **Imbalance and confounding, quantified** — group-size ratios for imbalance; **bias-corrected Cramér's V** (categorical↔categorical) or the appropriate association measure (continuous) for confounding between the contrast and each covariate/batch.

**Record the material gotchas as caveat findings** (`kind: caveat`, conventions/findings.md §2.6): a finding is warranted when an imbalance, skew, or confound would change how a downstream result is analyzed or interpreted. The thresholds are **judgment, not hard rules** — as rough orientation, treat a group-size ratio beyond ~3:1 (or any arm under ~10 samples), or a contrast↔covariate Cramér's V above ~0.3, as worth a careful look and likely a caveat. A recorded confound or imbalance has teeth downstream: a confounded covariate should **enter the model as a covariate** (or the comparison be stratified) rather than be silently ignored, and a class imbalance dictates **balanced metrics and stratified folds** in any classifier (see ML below). Carry the caveat into the affected finding's `caveats` via a `relates_to` edge.

## Sample set — analysis is on the experimental samples

- **Biological/differential analysis runs on the experimental subset only.** Control samples — pooled QC, reference/bridge channels, standards, blanks — are identified during metadata understanding (Stage 1) and certified at the integrity gate (Stage 3); they are **excluded** from every biological contrast. Including them silently distorts effect sizes, variance, and the null. The binary `experimental` vs `control` split, and the column or rule that derives it, are documented in `state/METADATA.md`; the analysis applies that documented rule rather than re-deciding the subset per script.
- **The exclusion is explicit and recorded, never silent.** Record the analyzed sample set in the finding's `provenance.params` — e.g. `sample_set: "experimental"` with the experimental-n and the count of controls excluded — so a reader can see exactly which samples produced the numbers and reproduce the filter.
- **Controls are not discarded — they carry the technical-QC role.** Pools quantify technical reproducibility (CV) and run-order drift; references/bridges anchor cross-batch comparison. They are viewed *separately* in QC (`conventions/visualization.md`), never pooled into the experimental distributions.
- **An annotation the data disagreed with was resolved at the gate, not re-litigated in analysis — and an inconclusive check is not a defect.** The Stage-3 *annotation concordance* check (`commands/stage3-loaders.md`; `conventions/correctness.md`) asks the data about an annotation only where a **near-binary marker** exists, and is deliberately conservative: the marker must validate on the bulk before any sample is flagged, only an unambiguous discordance is flagged, and the annotation stands unless the scientist decides otherwise. So the analysis sees one of three things — the annotation **as recorded** (concordant, inconclusive, not checkable, or a flag the scientist chose to keep), a **documented exclusion**, or a **documented loader override** — and applies it exactly as the loader does, never a per-script correction. A kept discordant sample, an exclusion, or an override is a **caveat finding** the affected discoveries link to (`relates_to`) and its consequence appears in `provenance.params` (`sample_set`, or the override named). The reviewer does not fail an analysis because a sex or genotype check came back *inconclusive*: that is the marker failing, not the labels, and it is reported as such.

## Test choice

- **Canonical over esoteric.** Prefer widely used, explainable tests; a reviewer and a reader should recognize the method.
- **Moderated models for differential abundance.** Prefer a **moderated linear model (limma / MSstats-style)** over naive per-feature t-tests — borrowing variance across features is both more powerful and more honest at omics scale. Nonparametric tests (Mann–Whitney) where distributional assumptions fail. The `lib/analysis/differential-abundance` template implements all four as one swappable family (`method=ols|moderated|welch|mannwhitney`, **moderated the default**) over a study-agnostic `contrast=` + `covariates=[…]` API, emitting the per-feature **effect (log2FC) + CI + p + BH-q** table this convention requires (the source oracle reported only effect + p; the CI is added here). Seed downstream visuals from `lib/figures/volcano` (effect vs −log10 q, hit counts) and `lib/figures/pvalue-hist` (the calibration diagnostic — a healthy run is uniform + a spike at 0; a U-shape/hump signals unmodeled structure or confounding).

## Normalization & batch correction

- **Normalization is a recorded scientific choice, not a silent default.** Recommend **median** to the scientist (simple, interpretable, linear in → linear out) and confirm it; offer **MAD** (robust per-sample z-score) and **VSN** (variance-stabilizing) as alternatives. Record the chosen method in the finding's `provenance.params`. Respect scale — MAD and VSN already log-transform internally, so never log again; for data that arrives already-log, use the log-domain `median_center` rather than re-normalizing from linear. The `lib/` `normalize` template carries a `scale` tag (`linear`/`log2`/`log10`/`ln`/`glog2`/`zscore`/`ratio`) and refuses the double-log at runtime.
- **Batch correction gets the batch label only.** When you correct for batch (ComBat, via the `batch-correct-combat` template), pass it the **batch variable and nothing else** — never the biological covariate of interest. Under confounding, handing the method the covariate to "protect" lets it attribute the confounded variance to biology and launder a batch artifact into the very signal you then test. Batch-only correction is the conservative choice: it cannot manufacture signal.
- **Prefer modeling batch over removing it — for significance testing.** ComBat removes between-batch variance *and* shrinks within-feature variance; feeding corrected values into a naive per-feature test understates standard errors and **inflates significance** (Nygaard et al. 2016). So for differential testing, prefer including **batch as a covariate in the design matrix** (limma / MSstats-style) over pre-correcting. Reserve ComBat *output* for visualization/clustering (PCA, heatmaps) and the both-ways robustness check below — not as direct input to a per-feature significance test.
- **Stage 3 previews batch correction; it does not commit to it.** When the design has a real batch axis (≥2 batches), the Stage-3 QC report shows the batch-corrected state *alongside* raw and normalized (PCA / CV / abundance box plots) purely to let the scientist **see the effect** — does control clustering tighten, does CV drop — and weigh it at sign-off. This preview is batch-label-only. It is **not** the testing decision above (batch-as-covariate, both-ways): that is settled in Stage 4. With a single plate/batch there is nothing to correct, so the batch-corrected panels are omitted.
- **Report corrected AND uncorrected as a robustness check.** Keep the uncorrected data and run the key analysis both ways. *Signal survives batch-only correction* → evidence it is robust to batch; *signal disappears* → confounded with batch, not cleanly attributable to biology. Two caveats keep this honest: under **partial** confounding, real biology is *attenuated* too, so a weakened-but-present effect is expected for genuine signal and is not itself an artifact; and because of the variance deflation above, treat a *more*-significant corrected result with suspicion rather than as strengthened. Carry the conclusion into the finding's caveats.
- **Surface the confound and get sign-off before correcting.** Quantify batch↔covariate confounding before any correction (`assess_batch_confounding`, bias-corrected Cramér's V). It warns when a covariate of interest is **perfectly confounded** with batch (constant within every batch → correction deletes its effect) *or* **strongly** confounded (above a threshold → correction attenuates it proportionally). Get explicit scientist sign-off on a flagged confound; do not silently proceed.
- **CV-by-processing-state is the QC readout that normalization (and batch correction) worked.** Overlay the per-feature CV distribution (std/mean, **linear scale**) across **raw → normalized → batch-corrected** states for the **experimental subset** (`lib/figures/cv-plot`, in the Stage 3 QC report); a drop in median CV is the evidence a step reduced nuisance variance. Render **one CV figure per control type** (pooled-QC, reference, standard, …) — control CV is a distinct technical-reproducibility readout (instrument precision / run-order drift), never pooled into the experimental overlay nor shared across control types. CV is undefined on a log scale and the template refuses it (as does **identification depth** — see below); since ComBat runs on log, the **batch-corrected** CV state is its output **de-logged to linear** via `normalize.to_linear` (a documented approximation — CV read on the linear image of a log-scale correction), and it appears only when batch correction was previewed (a real ≥2-batch axis). The abundance-boxplot, sample-correlation, and PCA QC plots, by contrast, read on **log** data (`conventions/visualization.md`). The **abundance box plot** (`lib/figures/abundance-boxplot`, log scale) is the complementary *per-sample* read of the same question: raw per-sample medians wander, a good normalization flattens them, and batch correction removes residual batch shift — stacked raw → normalized → batch-corrected.
- **Identification depth is the first-look QC of detection, before any normalization.** Detected features (finite & > 0) per run, on the **raw linear** matrix, one panel per level (protein / precursor), bars in acquisition order (`lib/figures/id-depth`, in the Stage 3 QC report) — it catches a failing/low-ID run or run-order drift that an abundance summary smooths over. Color by sample class and mark a reference-median over the experimental subset, so a dropout reads against where the real samples sit. Detection is a raw-data property, so the template **hard-refuses a non-linear scale** (`IdDepthScaleError`) — count it before the normalization step.

## Machine learning / prediction

- **No data leakage.** Every preprocessing step that *learns from data* — normalization, imputation, feature selection, scaling, batch correction — happens **inside** each cross-validation fold, fit on the training partition only, never on the full dataset first. Use scikit-learn `Pipeline` so the fit/transform boundary is structural, not manual. (For predictive models this *overrides* the global-normalization default above: fit the normalizer/ComBat on the training fold only.)
- **Match cross-validation to the generalization target.** Name the target first — *unseen samples, unseen individuals, or unseen batches?* — and hold out folds at that unit; report performance explicitly as "on unseen ⟨target⟩" and never claim a broader target than the folds held out. **Group folds only when the unit actually repeats** in the data (`StratifiedGroupKFold` on the `groups` column): when every individual appears once, a new sample *is* a new individual and row-level folds already estimate individual-level performance, so grouping singletons is pointless (and only hurts class balance). **The inner tuning folds are grouped whenever the outer folds are** (the templates do this and record `inner_cv_grouped`): a row-level inner split under a grouped outer CV puts a unit's replicates on both sides of a tuning fold, inflates the tuning surface (AUC ≈ 1 on pure noise) and picks hyperparameters that memorize the unit. A non-sample target needs `groups=` — the templates refuse `generalization_target="individuals"`/`"batches"` without it. When grouped, the label-shuffle null permutes at the **unit** level by default (`null_permutation="units"` — one label per unit, for a label that is a unit property) or **within** each unit for a batch-grouped design whose units hold both classes (`null_permutation="within_units"`; see *Two linear classifiers* below).
- **The shuffle null is the gate.** Permute the target — the class labels for a classifier, the continuous outcome for a regressor — and re-run the pipeline; if performance does not collapse to chance, either there is leakage or there is no real signal — and either way the coefficients are noise. Report the null distribution + empirical p alongside the real score. In `lib/analysis/classification` / `classification-svm` / `classification-xgboost` / `classification-lda` (label-shuffle on AUC) and `lib/analysis/regression` (target-shuffle on R²) the null is **opt-in** and **off by default** (`run_null=False`) because the compute cost is real — at default settings it adds ≈15,000 fits (1,000 permutations × 3 repeats × 5 folds) to a nested CV of ≈6,000 fits (elastic net, XGBoost, regression) or ≈1,900 (SVM) — **fit counts, not wall time; the cost of one fit sets the clock**. Measured: the **shrinkage LDA** null runs in **minutes** (2.3 min at 52 × 8,800; 5.8 min at 52 × 20,000; 8.6 min at 100 × 20,000; 21.5 min at 200 × 8,800 — its fit is O(n²p)), so the two-pass *order* still holds but its second pass follows **immediately in the same sitting**; the **XGBoost** null runs in **hours** (≈5.8 h at n = 40, p = 20,000; ≈38 h at n = 150 — 300 trees per fit), so its first null pass legitimately uses `n_permutations=200` (a p floor of 0.005) and a 1,000-draw confirmation follows only for a result worth it. **This makes the order deliberate: results first, null second.** The first pass fits, cross-validates, and reports the coefficients with their stability read; the null is then **proposed as the immediate follow-up**, not quietly dropped. Running it lets the finding reach **`validated`**; until it runs the finding is capped at **`exploratory`**, with the coefficients flagged "not tested against a null." The **stability loop stays in the first pass** — ≈1% of an elastic-net run, ≈3% of an SVM run, and it carries the per-feature trust read (§ selection evidence) that would otherwise be missing.
- **Elastic-net coefficients are a caveated interpretation, not an all-relevant selection.** An elastic-net model tuned for prediction — the classifier (`classify`) or the regressor (`regress`) — gives the *minimal-optimal* set; with correlated features L1 keeps one of a cluster and zeros its neighbours, so a **low selection frequency does not mean a feature is unimportant** — it may be redundant with a selected neighbour. Report the all-data standardized coefficients with their **cross-fold selection frequency + sign consistency** (the honest stability read) and state this caveat in the finding. The *all-relevant* question belongs to Boruta, not the elastic-net model.
- **Linear vs non-linear classifier — pick by the question, run both if unsure.** The elastic-net classifier (`classify`) is **linear, sparse, and signed** — best when `p ≫ n` and the class signal is roughly additive, and its signed coefficients read as direction. The **gradient-boosted-tree** classifier (`classify_xgboost`) is **non-linear** — it captures interactions and non-monotone effects a linear model misses — but its **importances are unsigned** (`total_gain` by default — the summed split gain; the per-split average `gain` flatters a feature used once in a strong split — a magnitude, no direction), it is more prone to overfit on small-n proteomics, and it is harder to interpret causally. Both obey the **same leakage discipline** (nested CV, group-aware-when-repeats, opt-in shuffle null, the stability read) and the *same* minimal-optimal caveat (a low selection frequency ≠ unimportant; the all-relevant question is still Boruta's). Two tree specifics the reviewer should expect: trees are **scale-invariant**, so `classify_xgboost` does **not** standardize and does **not** warn on a non-log scale (unlike `classify`); and it handles imbalance with a **fold-local `scale_pos_weight`** rather than `class_weight`. Offer the tree model alongside — not instead of — the linear one, **on a trigger**: the elastic net's nested AUC sits within seed noise of chance while univariate DE or Boruta show clear signal, or an interaction hypothesis was stated *before* the run. It joins the same paired rule as the linear alternatives (all four templates record fold identity): compare it **paired per fold against the elastic net** with `lib/analysis/classifier-comparison` (reading `"non-linear"`), and treat it as cleanly fitted only when `best_params` sit off the grid border.
- **Two linear classifiers — sparse elastic net or dense max-margin SVM.** The **linear SVM** (`classify_svm`, soft-margin `SVC(kernel="linear")` with `C` tuned; the hard-margin SVM is its large-`C` limit) is the second linear model. It is **dense and signed**: a max-margin weight vector spreads weight across correlated features (ridge-like) where L1 keeps one and zeros the rest, so it is the model to offer when the elastic net's sparsity is undesirable or many co-regulated features carry the signal, and it suits the separable small-*n*/high-*p* regime. Three consequences the reviewer should expect: (1) **no selection frequency** — every feature is non-zero, so the stability read is the **top-k membership frequency** (fraction of stability resamples in which the feature ranks in the top *k* by |weight|) beside sign consistency and the weight IQR, and the coefficient table holds *every* feature; (2) **scores are margins** (`decision_function`), **not probabilities** — no calibration is run (AUC is rank-based), balanced accuracy thresholds the margin at 0, and support-vector counts are reported; (3) a **1-D `C` grid** whose inner-CV curve **plateaus** on separable data — the **smallest `C` on the plateau** is chosen (most regularized among the maxima), so a `best_c` at the top of the grid means the data wanted the hard margin. (The smallest-vs-largest tie-break was **measured**, paired on the same inner searches across two datasets and 200 outer folds: the held-out AUC is identical in 90–99 % of folds and the mean difference sits inside seed noise, so there is no `tie_break` option — the largest rule is just the grid top, which `c_grid=(1e6,)` already pins.) Where the plateau begins scales roughly with **1/n_features** (the default grid reaches down to `1e-5` for a whole-proteome matrix; a small panel shifts the knee up), and the template **warns (`CGridEdgeWarning`) when the selected `C` sits at a grid edge** — the grid did not bracket the optimum; extend it and re-run rather than report the edge value as "tuned". The opposite failure is a grid **wider than tiny inner folds can resolve**: with ~30 training samples the inner AUC is coarse, several `C` values tie, and some outer folds tune *below* the plateau, lowering the nested estimate through tuning noise rather than data (measured on a 40-sample study: ~0.03 AUC vs a grid whose floor sat at the knee). The result records the all-data **plateau start** and the **number of outer folds that tuned below it**, the C-curve figure draws the per-fold picks, and a **`TuningNoiseWarning`** fires past 25 % of folds — the response is to **narrow `c_grid` to bracket the knee** and re-run, and to compare classifiers on the same seed, since seed alone moves a 40-sample nested AUC by ±0.03. **The null's permutation scheme follows the unit (`null_permutation`, all four classifier templates):** when `groups` is a subject/animal each unit carries one class and the default `"units"` scheme permutes *unit* labels (a unit holding both classes is refused rather than silently mis-permuted); a **batch-grouped design** (`generalization_target="batches"`, batches holding both classes) runs its null with `"within_units"`, which shuffles labels *inside* each batch, preserving every batch's class counts — the restricted permutation for exchangeable blocks (Anderson & ter Braak 2003; Winkler et al. 2015), testing whether the proteome predicts the label *beyond batch*. Because `StratifiedGroupKFold` assigns units to folds from their class counts, every null draw is scored on the observed folds and only the labels move. It needs grouped CV with some mixed unit (all-single-class units raise — the shuffle would be the identity and p = 1; fewer distinct arrangements than permutations warn, `NullPermutationWarning`) and assumes samples within a unit are exchangeable (a nested subject-within-batch design needs a multi-level block permutation — not offered). The scheme applied is recorded on the result (`null_permutation`: `samples` / `units` / `within_units`), named in the null figure's title, and is a fingerprint param (`conventions/results-cache.md`). Same leakage discipline and minimal-optimal caveat as the elastic net. **Compare classifiers paired, not pooled:** all four classifier templates record fold identity (`repeat`/`fold`/`test_indices`) and build their outer CV identically, so two templates run with the same seed on the same analyzed samples are evaluated on the **same folds** — compare per-fold AUCs pairwise with **`lib/analysis/classifier-comparison`** (`compare_classifiers` aligns the folds by identity and refuses a different seed or sample set; it returns the per-fold table, win/loss/tie counts, the **corrected resampled t** — the folds are dependent, so that is the decisive p — and a Wilcoxon on the non-zero differences labelled *indicative*; `compare_across_seeds` applies the sign-across-seeds rule — *Choosing among the linear classifiers*), never just the two means.
- **Three linear classifiers — the shrinkage LDA is the tuning-free dense model.** The **shrinkage LDA** (`classify_lda`; `lib/analysis/classification-lda`) is the third linear model: the Gaussian classifier with a shared, **Ledoit-Wolf-shrunk** within-class covariance, whose discriminant direction is the **covariance-adjusted mean difference** `S⁻¹(μ_pos − μ_neg)` — which proteins separate the classes *after* accounting for how proteins co-vary, the DE-like direction the other two do not give. It is solved in the **dual (Woodbury) form**, so a fit costs milliseconds at 20,000 features (scikit-learn's own solver forms the p×p covariance and is unusable past a few thousand); the in-module numerics are pinned to scikit-learn at machine precision by the test suite. Four consequences the reviewer should expect: (1) **nothing is tuned** — the shrinkage intensity is analytic per fold, so "nested CV" is plain repeated stratified CV (still leakage-safe: scaler + shrinkage fit on the training fold only), there is no grid, no tuning figure (the template ships **three** figures), and no `CGridEdgeWarning` / `TuningNoiseWarning`; the diagnostic that replaces the tuning read is the **per-class shrinkage intensity** λ, recorded per fold and for the all-data fit, with a **`ShrinkageSaturationWarning`** at λ ≥ 0.95 — the covariance then carried nothing and the weights are ≈ a standardized mean difference (diagonal LDA), so the *reading* changes while the comparison stays valid; (2) **dense signed weights** read through the **top-k membership frequency** (the SVM convention; the table holds every feature); (3) **scores are calibrated log-odds** (the log posterior ratio under class-frequency priors — `sigmoid(score)` is the posterior; balanced accuracy thresholds at the **equal-prior cut** — the training fold's log prior ratio, the operating point `class_weight="balanced"` gives the siblings, so it is comparable across the three; there is no `class_weight`, imbalance enters the *scores* through the priors); (4) **its null is minutes, not hours** (measured scaling under *The shuffle null is the gate*) — run it right after the first pass, in the same sitting. **Offer it beside the elastic net when** the SVM's `TuningNoiseWarning` cannot be resolved at small *n* (the LDA has nothing to tune), a **covariance-adjusted reading** is wanted, or the null must be affordable **now** (a validated-grade claim is needed in this sitting). Same leakage discipline, fold identity, null schemes, `feature_list=`, and minimal-optimal caveat as the other two. **The evidence** (2026-09-17 preview, same folds as the shipped templates): on 5xFAD genotype LDA 0.848 sat between the elastic net (0.905) and the SVM (0.796), beating the SVM at all three seeds, with the canonical AD set (APP + the transgene, APOE, midkine, TICN1/2, clusterin, the C1q trio) at 0.83 top-20 fold-membership and 17/20 overlap with the elastic net; on MagNet-EV (n = 40) LDA 0.950 tied the SVM (0.963) and beat the elastic net 10/0/15, but its weights were unstable (0.45 membership) — the membership read is what stops a dense list being mistaken for a stable feature set. **Binary outcomes only (v0.1)**; a multiclass-native v0.2 is the planned extension (the design's four-class MagNet run reached macro AUC 0.957).
- **Choosing among the linear classifiers — default, trigger, decision.** **Default to the elastic net** (`classify`): it is seeded first in Stage 4, and its sparse signed coefficients answer the question most studies ask first (*which few features carry the class?*) — not because it is cheaper (its first pass is ≈6,000 fits against the SVM's ≈1,900 and the LDA's milliseconds). **An alternative is run on a trigger, never by default, and is compared paired against the elastic net — never all-pairs** (each extra candidate scored on the same folds enlarges the winner's-curse bias below, so the elastic net is the reference every alternative is measured against, not one entrant in a tournament). **Offer the linear SVM alongside** (`classify_svm`, same seed) when any of these holds: the scientist wants a **module-level reading** (a co-regulated cluster read as a whole rather than one representative of it); the elastic-net **selection is unstable** (low selection frequency across a correlated cluster while sign consistency stays high — L1 is picking an arbitrary representative); or the elastic net's own tuning says the data want a dense model — `best_l1_ratio` at the **ridge end** of its grid, or a selected set that changes across seeds / resamples while the AUC does not. (A near-perfect *training* fit is not a trigger: every `p ≫ n` matrix is linearly separable in training.) **Offer the shrinkage LDA alongside** (`classify_lda`, same seed) when: the SVM's **`TuningNoiseWarning` cannot be resolved** at small *n* (the LDA has nothing to tune); a **covariance-adjusted reading** is wanted (which proteins separate the classes *after* accounting for co-variation); or the null must be **affordable now** (a validated-grade claim in this sitting — its null runs in minutes at 20,000 features — 5.8 min at n = 52, 8.6 min at n = 100). **Before the alternative runs, two things are settled.** (1) **Name the reading wanted** — a sparse minimal set (elastic net), dense max-margin module weights (SVM), or the covariance-adjusted direction (LDA) — *before* either feature list is on the table; a tie (below) is decided by that pre-stated reading, and choosing the reading after seeing which list tells the better story is the motivated-reasoning pressure the gates exist to resist. (2) **The alternative must be cleanly fitted first**: for the SVM a `CGridEdgeWarning` or `TuningNoiseWarning` is resolved (narrow or extend `c_grid`, re-run) *before* any comparison — an elastic-net "win" over an SVM whose grid let the inner folds tune below the plateau is an artifact of the grid, not evidence about the models; for the LDA a `ShrinkageSaturationWarning` is **acknowledged** — the comparison stays valid, but its weights are then a standardized mean difference, not the covariance-adjusted reading that triggered it. Do not choose on the mean AUCs. **Decide on the paired per-fold comparison**, computed by `lib/analysis/classifier-comparison` (`compare_classifiers(reference, alternative, reading=…)` — the pre-stated reading is a required argument and is recorded on the result; the figure is `lib/figures/classifier_comparison`): same seed, same splits, the per-fold differences and the win/loss/tie counts are the **primary evidence**. If a p is wanted, remember the folds are **not independent** — folds within a repeat share most of their training data and repeats reuse the same samples — so a Wilcoxon signed-rank over the 25 fold pairs is **anti-conservative**; the template reports the **corrected resampled t-test** (Nadeau & Bengio 2003; per-fold `n_test/n_train`) as the decisive p and a Wilcoxon on the non-zero differences labelled *indicative only*. Read the result against **seed noise**, and let the data say how big that is: a real preference is one whose **sign holds across a few seeds** (three is a reasonable minimum; `compare_across_seeds` takes the per-seed pairs and returns `sign_consistent` and a `verdict` — `tie` unless the sign holds) — the rule is sign consistency, not a fixed band. As an example of scale, on a 40-sample study the nested AUC moved by about ±0.03 between seeds; a study's own band can be larger or smaller. A paired difference that does not hold its sign across seeds is a **tie**, decided by the pre-stated reading, never by the higher number. **Report every AUC that was run, not only the winner's** — picking the better of several models on the same nested CV is a selection step outside the CV, so the winner's estimate carries an optimistic bias that grows with the number of candidates (small with two; the reason an alternative is run on a trigger, not by default, and the reader should see every result). The **tree model joins this rule** on its own trigger (*Linear vs non-linear classifier*), compared the same way with reading `"non-linear"`. Whichever wins, the models answer different feature questions and **none is the all-relevant answer** (Boruta); a feature several rank highly is the robust one. Record the comparison (every fingerprint and AUC, the paired statistics, the seeds, the pre-stated reading) in the finding, and carry the losers' results as `superseded`, not deleted. **The evidence for this rule is two-sided**: on 5xFAD genotype the elastic net won by 0.11 on the shared folds (the LDA sat between at 0.848, beating the SVM at every seed); on MagNet-EV the SVM won by 0.03 at every seed and was never worse on a shared fold, and the LDA tied it while beating the elastic net 10/0/15 — no model dominates, which is why the comparison, not a fixed pick, is the rule.
- **A prior feature list is a legitimate, encouraged restriction — if it is outcome-independent.** For the leakage-safe classifiers and regressor, restricting to a curated / hypothesis-driven feature set (domain proteins of interest; e.g. a published radiation-responsive panel) before fitting cuts dimensionality (proteomics is `p >> n`), can sharpen a weak signal, and aids interpretability — **`classify`, `classify_svm`, `classify_lda`, `classify_xgboost`, and `regress` all take a `feature_list=`** (applied once to the whole matrix, leakage-safe because the list is outcome-independent) and record matched/unmatched counts in `provenance.params`. **The list must be defined independent of this outcome** (a list derived from this same data's contrast is circular and leaks); a published or domain list is fine. Offer it alongside the whole-proteome run.
- **Boruta answers the all-relevant question — and its shadows are a built-in null.** Where the elastic-net classifier gives the minimal-optimal set, **Boruta (`lib/analysis/boruta`) confirms *every* feature carrying signal**, so a whole correlated cluster is recovered rather than one representative — the two are complementary (run both; a feature the classifier zeroed but Boruta confirms is redundant-but-real, not noise). Boruta's **shadow (permuted) features are its own null**, so it satisfies the label-shuffle-null requirement *intrinsically* and needs no external null; and because its output is a *selection*, not a held-out performance estimate, it legitimately runs **once on the whole experimental matrix** (no CV, no fold machinery — the canonical wiring even feeds it the ComBat-corrected matrix, a legitimate use of ComBat output since this is selection, not a per-feature significance test). The **in-fold-preprocessing / group-aware-CV rules above bind any downstream *performance* claim on the selected set, not the Boruta selection run itself.** Its evidence is a **decision (Confirmed / Tentative / Rejected) + per-feature importance vs the shadow threshold** — the *selection* evidence kind (no per-feature q; conventions/findings.md §2.3), the same kind the classifier's coefficient/stability report uses. **The default run (`max_iter=100`, `alpha=0.05`, `perc=100`) is a starting point, not a fixed contract:** if **too few** features Confirm, raise `max_iter` (~`200`) and/or lower `perc` toward `95`/`90` (a more lenient shadow floor); if **too many** for a tractable downstream analysis, lower `alpha` to `0.01` (a stricter accept/reject bar). Any non-default is a recorded choice — it enters `provenance.params` and the cache fingerprint, so a tuned run is reproducible and cached distinctly from the default.
- **Outcome↔covariate confounding is surfaced, not silently corrected.** A *consequential* imbalance between the outcome and a metadata variable (a Stage-1 caveat, gated by consequence — the same graded Cramér's-V bar, not every histogram) lets the classifier or regressor select confounder-proxy features. Surface it collaboratively, in plain language (the scientist is not a statistician), and decide together whether to address it (restrict / adjust) or carry it as a loud caveat; do **not** bake a blanket correction into the template.

## Enrichment / over-representation (GO / KEGG)

Downstream of feature finding/selection: given a **query** (a DE hit list, a Boruta-confirmed set, a classifier-selected set, a cluster) plus a **background**, ask which GO terms (BP/MF/CC) and KEGG pathways are over-represented. Ships as `lib/analysis/enrichment` (`enrich(...)`, g:Profiler) + the three `lib/figures/enrichment` figures. The rules the **stats-reviewer** checks:

- **Confirm the ID→UniProt encoding with the scientist *before* running — a hard checkpoint.** g:Profiler keys on gene ids; the template maps protein ids to UniProt accessions with a generalized, **swappable** parser (`sp|…`/`tr|…`/bare/isoform/protein-group; a contaminant mnemonic drops out). **No parser can be assumed correct for an unknown study**, so show the scientist the decoding (`build_mapping_audit` — per-source counts, mappable %, worked `original → accession` examples, and the full **unmappable** list) and get **explicit sign-off**; if the scheme is unusual they supply guidance or a custom `id_parser=` (a one-function fix, not a template edit). The decode audit is written to disk and pinned in the finding's `provenance`. This is the analysis analogue of the Stage-2 normalization / control-detection sign-offs — enforced by the Stage-4 checkpoint + stats-reviewer, no clean hook.
- **Background = the experiment's detected, mappable proteome** (`domain_scope="custom"`), **not** the whole genome. A whole-genome background trivially inflates terms ubiquitous in the measured tissue (on real 5xFAD it turned ~15 honest terms into 250, dominated by "cytoplasm"/"protein binding"). The query must be a **subset** of the background (enforced). Analysis is on the experimental subset (controls excluded upstream, as everywhere).
- **Correction is g:Profiler's g:SCS by default** (GO-graph-structure-aware; g:Profiler's own recommendation and the conservative choice), with `fdr`/`bonferroni` selectable and recorded. **Report all significant terms** (the full table to CSV), not a hand-picked few; every term carries its **corrected p + set sizes + gene ratio** (the ORA analogue of *no bare p* — the evidence is a term-level statistic, so there is no per-feature q; `conventions/findings.md` §2.3).
- **Directional ORA is the standard.** Enrich the up- and down-regulated hits **separately** (`enrich_from_differential_abundance(..., direction="up"|"down")`) — far more interpretable than the merged list — with the merged view available.
- **Record the g:Profiler data version.** g:Profiler is a **live, versioned service** (the only `lib/` template that hits the network); a result is only reproducible against a stated Ensembl/GO/KEGG release, so the returned `gprofiler_version` is captured into the finding's `provenance` (the analogue of a seed); pin `base_url` to an archived release for exact reproducibility. A network/service failure **raises** (never a silent empty enrichment).

## Power & honesty

- **Be honest about power.** Treat small-n results as **`exploratory`** by default (conventions/findings.md §5). Don't dress an underpowered observation as a confirmatory result.
- **Confounds are first-class.** A confounded comparison (variable of interest aliased with batch/run-order) limits what any statistic can claim; surface it (detected in Stage 1, quantified by `assess_batch_confounding` before any batch correction) and carry it into the finding's caveats.
