# Engine-development / CI dependency set for building & testing the lib/ template
# scripts in THIS repo. Pinned to the known-good environment the committed test
# suite passes against (mirrors the strict bar in conventions/coding.md). The
# .venv it populates is git-ignored and regenerable: `pip install -r requirements-dev.txt`.
#
# This is the ENGINE-DEV env only — it never ships to or governs a user's project.
# A user's project env is separate, seeded by `setup-env` and pinned in their uv.lock.
#
# DELIBERATELY NO type-stub packages (pandas-stubs, scipy-stubs, types-*): a user's
# setup-env project won't have them, so the templates must pass `mypy --strict` against
# the libraries' own bundled types. Stubs installed locally can MASK real strict-typing
# errors (e.g. pandas-stubs types Series.to_numpy() precisely; without it mypy sees Any
# and flags no-any-return). CI installs exactly this set, so it catches what a dev .venv
# carrying stubs would hide — keep stubs out of this file.
